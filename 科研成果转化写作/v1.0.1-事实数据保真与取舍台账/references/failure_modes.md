# 基础 Agent 常见失败模式与本 Skill 对策

1. **数字漂移**：改写时凭印象把 85.3% 写成 89%、62.1% 写成 65%。对策：正向逐值核验，同量纲不同值判 altered（critical）。
2. **源外新事实**：为"更好看"擅自加"能量密度提升 40%"等源文没有的数据。对策：反向逐 token 溯源，无对应即 unverified（critical）。
3. **静默丢数据**：整段压缩时把含关键结论/数据的段落一并删掉，事后无记录。对策：ledger 强制关键段落逐段决定；删除必须给理由并列出丢弃事实。
4. **图表编号臆造/错位**：改写稿引用"见图3"但源文只有图2。对策：图表编号双向一致性，unknown 判 critical。
5. **无台账写作**：先成稿后补理由，导致删除理由与真实改动对不上。对策：SKILL.md 规定"先写 retention_decisions.jsonl 再写改写稿"。
6. **单位乱换**：把 5 nm 写成 5 μm（量级错误）或"约 5 个纳米"。对策：换算只认可换算表内的等价量级，5 μm 与 5 nm 不同值 → altered。
7. **百分数换小数失真**：0.853 写成 0.85 或 8.53%。对策：derived 容差 ±1%/四舍五入，超出即 missing/unverified。
8. **拿化学式/年份当数据**：把 LiNi0.8 的 0.8、2023 年当作"源外数值"误报，或反向利用遮蔽塞入新事实。对策：遮蔽规则跳过这类 token，同时要求实质性新事实人工确认。
9. **只给建议不给稿**：输出"保真改写建议清单"。对策：SKILL.md 明确"完整成稿"红线，validate 闸门要求 rewrite.md 非空。
