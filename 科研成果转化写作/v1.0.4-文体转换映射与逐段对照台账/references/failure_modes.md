# 基础 Agent 常见失败模式与本 Skill 对策

1. **为凑文体结构编造内容**：写新闻通稿时虚构研究者引语、联系方式；写申报材料时自编预期指标。
   对策：genre_engine map 标出缺失要素，SKILL.md 红线一要求标注「源文未提供」，严禁编造。
2. **悄悄删除含数据的段落**：改写时漏掉对照组数据、限定条件，读者与作者都无从察觉。
   对策：ledger 中「源文段落未被覆盖且 change_reasons.jsonl 无删除理由」= critical，exit≠0 不得交付。
3. **新增段落夹带源外事实**：过渡句里顺手写入"国际领先""效率提升 30%"等源文没有的论断与数值。
   对策：新增段落未标「新增-过渡」= warn；新增段落含数值+单位时引擎逐条提示核对来源。
4. **理由与实际行动不符**：理由写"保留"但段落实际彻底重写，溯源时对不上。
   对策：ledger 比对 reasons 的 action 与 align_rewrite 的 sim（如「保留」但 sim<0.12 判新增 → warn），
   提示核实是事实漂移还是理由笔误。
5. **文体错配**：把通稿写成摘要（无导语无背景），或把简报写成全文（无取舍）。
   对策：4 套内置模板固定结构要素与顺序，map 先出要素映射再动笔；简报关键数据限 ≤5 条。
6. **论断强度漂移**：「初步表明」写成「证实」，「有望」写成「已经」。
   对策：SKILL.md 写作要求明确强度一致；模板写作要点逐要素提示强度限定词；
   逐段理由要求说明动作（保留/压缩/改写），改写段落在台账中可与源句直接对照。
7. **台账事后补造**：写完稿子再凭印象补理由，理由与实际改动脱节。
   对策：SKILL.md Phase 3 要求"边写边记"（逐段同时写 jsonl）；action_contradiction warn 暴露脱节。
8. **只给稿不给账**：基础 Agent 常只交付成稿，评审无法复核改动。
   对策：ledger 自动生成人读 traceability_report.md（两表+问题清单），validate 闸门要求证据非空。
