# 意见分类与落实判据（revision_rules）

## 1. 意见类型归类（parse 自动判定，Agent 可复核）

| 类型 | 触发词（type 或 content 中） | 典型落实方式 |
|-|-|-|
| 补充 | 补充/添加/增加/增补/写明/加入 | append_after 在定位段后插入，或 replace 扩写该段 |
| 删除 | 删除/删去/去掉/移除 | replace：删去指定句/词后的整段（不得留半截病句） |
| 改写 | 改写/重写/修改/改为/表述为 | replace 整段，保留原意与数据 |
| 结构调整 | 结构/顺序/移动/合并/拆分 | 多段联动；逐段 replace，台账注明结构变化 |
| 格式 | 格式/排版/统一/编号样式 | replace 统一格式；不得借机改动实质内容 |
| 引用 | 引用/文献/注释/出处 | replace 补引用标记；文献信息须来自文献库 |
| 其他 | 无法归类 | 按语义选择最接近的落实方式，reason 中说明 |

## 2. 落实（edit）写作判据

1. **保原意**：new_text 必须保留原段落的核心论断、数据、术语写法；只改意见要求的部分。
2. **完整段**：mode=replace 时 new_text 是替换后的**完整段落**，不是差异片段。
3. **可溯源**：新增数值/事实必须来自 materials 或文献库；溯源不了就不新增，
   改为定性表述或在 reason 中声明"数据待补"。
4. **一段一意见**：一次 edit 只动一个 target_pid；一条意见确需动多段时，
   拆成多条 agent_edits 记录是不允许的（rid 唯一）——选择主段落 replace，
   其余在 reason 说明，或改用 append_after 集中处理。
5. **不碰其他文件**：edit 只作用于该意见的 target_file；跨文件联动改写在
   reason 中声明并由 Phase 4 复核。

## 3. 状态判定（引擎裁定，Agent 不得口头覆盖）

| 状态 | 触发条件 |
|-|-|
| 已落实 | action=edit 且文本替换/插入成功 |
| 部分落实 | 原文段落已解析但文件内文本匹配失败（文件被并发改动） |
| 无法落实 | action=skip；或目标文件缺失；或找不到对应原文段；或 edit 缺 new_text |
| 待人工确认 | action=defer；或 agent_edits.json 中漏了该 rid |

## 4. 冲突裁决规则

- locate 检出的 conflict（同 pid、补充 vs 删除）：**不得两条都 edit**。
  裁决方式：语义上更权威/更晚轮次的意见 edit，另一条 skip/defer 并写明
  "与 R-x 冲突，经裁决保留 R-x，理由：……"。
- 多轮覆盖：round 升序执行；后轮推翻前轮已落实内容时，台账注明
  "第 N 轮意见覆盖第 M 轮"，净效果以 diff_report 为准。

## 5. 复核验收清单（Phase 4 逐条过）

- [ ] 重跑 locate 后 top1 pid 仍落在原段落；
- [ ] 修订稿中包含 after 摘录的关键表述（抽查关键词）；
- [ ] diff_report 中除台账记录外无意外差异；
- [ ] 章节标题、编号、引用标记数量与改前一致（除非意见本身要求改）；
- [ ] 每条"无法落实"都有具体原因，每条"待人工确认"都进了 uncertainty.json。
