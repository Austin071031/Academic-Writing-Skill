# failure_modes.md — 已知失败模式与对策

| # | 失败模式 | 表现 | 对策 |
|-|-|-|-|
| F1 | 材料文件名无提示词 | build 打印「未识别出材料文件」WARN，omissions 为空，材料遗漏防护失效 | 用 `--materials-regex` 显式指定（如 `--materials-regex "record|记录"`），重跑 build 与 brief |
| F2 | 语义复述漏检 | 后写章节换说法复述前文，4-gram 字面重合低，重复论述漏报 | 重复结论检查（同主语+关键数值）兜底；Agent 在 Phase 4 阅读 overlap_report.md 时人工扫一遍「前文已下结论」清单 |
| F3 | 套话误报 | 两章都有完全相同的过渡句/实验步骤句 → 重复论述命中 | 设计上视为应修复项：学位论文中整句照抄本来就不允许；确属必要的（如设备参数句）在 manual_confirmations 登记 |
| F4 | 定义抽取脏 term | 「是/采用」等动词被吞进 term | 引擎已剥前导动词；仍异常时在 dossier.md 人工核对，术语引用以 dossier.json 为准 |
| F5 | 结论动词误命中 | 「本研究结果表明…的综述」类句子被登记为结论 | 结论登记宁宽勿窄：overlap 的重复结论还需同主语+共享数值才报，误登记不会直接导致误报 |
| F6 | 化学式/型号误判为缩写 | Li6PS5Cl、B7 被当作未定义缩写 | 引擎仅把全大写且 ≥2 字母的 token 视为缩写候选，化学式与批次号已豁免 |
| F7 | 跨语言重复漏检 | 前文英文段落与中文 draft 语义重复但字面无重合 | 已知边界（dossier_rules §6）；依赖 Agent 读 brief 时的双语自查 |
| F8 | brief 预算截断丢关键定义 | 目标章节与某定义字面零相关，相关性排序将其排后并被预算截断 | brief 如实记录截断量；截断 >0 时提高 `--budget-chars` 重跑，或直接把 dossier.md 的定义节（通常很短）一并读入 |
| F9 | 图表编号体系不一致 | 前文用「图2-1」draft 用「图1」，dangling 检查按字符串精确匹配 | 新图表编号沿用前文体系（brief 第⑤桶给出已有 caption）；dangling 命中后先核对是否编号风格问题 |
| F10 | 预算耗尽中途停工 | 长文档写作迭代多，64 次请求不够 | Phase 0 骨架 result.json 防空手；40 次请求后按 SKILL.md §3 兜底 partial 交付 |
| F11 | draft 自带定义未被识别 | draft 用「X 又称 Y（ABBR）」等非常规定义式 | 改用标准定义式「全称（英文, ABBR）」或「X 是指…」；引擎判据见 dossier_rules §2.1 |
| F12 | 材料条目过短被跳过 | 归一化长度 <8 的材料段落不进使用矩阵 | 属设计取舍（过短条目相似度不可靠）；在 dossier.md 可人工复核原始材料 |
