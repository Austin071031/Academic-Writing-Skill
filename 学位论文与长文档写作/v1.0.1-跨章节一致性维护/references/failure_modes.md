# 已知失败模式与对策（failure modes）

## 引擎层（启发式固有边界）

1. **主语 n-gram 是字面启发式**：语义相同但字面改写（"电导率提升" vs "离子传导能力
   增强"）的矛盾对会漏检。对策：Agent 在 Phase 3 通读各章结论段，不依赖候选清单完备。
2. **极性只看否定词**：双重否定（"并非不能"）、程度副词（"显著提高" vs "略有提高"）
   会误判或漏判极性。对策：矛盾候选一律人工裁决，引擎不自动判错（设计如此）。
3. **高频复合词可能收进非术语**："本文研究结果表明"类套话若高频会进候选。
   对策：Agent 审定时 `keep=false` 剔除；这也是 review 步骤存在的原因。
4. **缩写定义模式要求括号紧邻**：定义写成"全固态电池，简称 ASSB"不命中模式 (a)，
   但若 ASSB 高频会进 (c) 类候选，Agent 可在 review 中手动补 canonical/variants。
5. **英文单复数归一很粗**（去尾 s）：bias→bia 这类过度归一会把不同词误判同写法；
   只在"比较是否同一写法"时使用，不用于改写，风险可控。
6. **图表编号归一假设 `3-1`≡`3.1`**：若论文刻意混用两套编号体系（图3-1 与 图3.1
   是不同图），会误判为同一定义。对策：编号体系混用本身已在异常表中要求统一。
7. **跨章比对按文件（C01/C02）划分**：单文件多章的稿件（一章文件内含多个 `# 第X章`）
   矛盾检测退化为全文比对，可能漏"跨章"语义。对策：stats 记录 single_chapter，
   Agent 人工补查。
8. **影响面的结论句重叠传播只有一跳**：改动 A→影响 B→B 又影响 C 的二阶传播不展开。
   对策：对 impact 结果中的关键段落可再做一次 impact 迭代。

## 流程层

9. **glossary_review.json 由 Agent 手写**：格式错误（非列表、缺 canonical）会让
   glossary 子命令直接报错退出。对策：严格按 SKILL.md 的 schema 写；报错后修正重跑。
10. **删除 xref_audit.json 蒙混交付**：validate 只在文件存在时检查 dangling。
    红线禁止；评审时以 git/change_log 核查。
11. **改稿后不复核**：口头声称"已统一"是红线 3 禁止项；必须重跑 scan+glossary
    以 consistency_report 异写清零为准。
12. **长文档性能**：n-gram 统计与两两结论比对分别为 O(文本×n) 与 O(结论句²)。
    结论句 >2000 句时矛盾比对约 200 万次集合运算，秒级可完成；再大建议分文件
    分批 scan 并在 stats 记录。
