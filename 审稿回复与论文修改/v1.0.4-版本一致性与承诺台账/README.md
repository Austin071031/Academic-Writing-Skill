# 审稿回复与论文修改 Skill · v1.0.4 版本一致性与承诺台账

玻尔产品周赛第四期「审稿回复与论文修改」参赛作品（方向：版本一致性）。

## 这是什么

一个可被 Agent 调用的 Skill：读入基线稿件 + 审稿意见，驱动一次受控返修，并以**真实行级 diff** 为事实源，把"回复信声称的修改、实际应用的编辑操作、稿件真实差异"三方对账闭合；多轮返修时嗅探上一轮回复信，抽取承诺句式逐条核对兑现，交付修订稿、逐条回复信、对账报告与跨轮承诺台账。

## 与基础 Agent 的差异（创新点）

1. **声称↔操作↔实际 diff 三方对账**：不再满足于"回复信说的修改能在成稿里找到子串"，而是要求每个 applied op 的新文本落在 difflib 计算出的**差异区域内部**——落在未变区域视同没改，直接 FAIL；
2. **未声明改动检出**：反向核对每个 diff region 是否被编辑操作认领，修订稿里多出回复信未交代的改动即 WARN 列出（重排噪音自动豁免），杜绝"悄悄改稿"；
3. **承诺台账跨轮追踪**：嗅探历史回复文件（response/reply/回复/rebuttal/round/r1 命名），抽取承诺句式（将/会/下一步/下一轮/we will），关键词重叠判定兑现状态；占位兑现只记"部分兑现"，不记"已兑现"；
4. **轮次感知**：从 case.json 的 constraints.round / revision_round 读取当前轮次；第 1 轮记"无历史承诺"，round>1 却嗅探不到历史文件时 WARN 提示而非静默放过。

## 快速开始

平台自动加载时无需手工操作；独立复用见 [docs/USAGE.md](docs/USAGE.md)。方法、边界与红线见 [SKILL.md](SKILL.md) 与 references/。

## 依赖与限制

Python 3.8+ 标准库，零第三方依赖。只修订输入中实际提供的基线；不补做实验、不编造数据，未到位证据一律【待补】占位 + 清单 + 人工确认。承诺兑现判定基于关键词重叠，属启发式，"无法判定"与边界情形一律交人工确认，不替作者下结论。
