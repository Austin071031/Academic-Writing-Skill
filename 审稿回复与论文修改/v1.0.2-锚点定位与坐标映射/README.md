# 审稿回复与论文修改 Skill · v1.0.2 锚点定位与坐标映射

玻尔产品周赛第四期「审稿回复与论文修改」参赛作品（方向三：修改定位）。

## 这是什么

一个可被 Agent 调用的 Skill：读入基线稿件 + 审稿意见清单，驱动一次可复核的受控返修，交付修订稿、逐条回复信与**可独立核对的修改定位**——每处改动同时标注基线坐标（章节+段 ID+基线行号）与修订稿坐标（行号+段 ID+新文本摘录），回复信里的每一个定位声明（E#、引文、坐标）都由引擎对照修订稿自动核验，核不到就拒绝交付。

## 与基础 Agent 的差异（创新点）

1. **双坐标定位**：一处改动、两套坐标——基线侧（章节标题、P###、基线行号）与修订侧（修订稿行号、段 ID、新文本前 30 字）成对记录，互相印证，改稿后仍可回溯核对；
2. **行级 diff 映射**：difflib.SequenceMatcher 对基线↔修订稿全文做行级对齐，自动生成 change regions（基线行区间→修订稿行区间）并把每个编辑操作反查到所在区域，Agent 不再手抄行号，杜绝旧稿行号残留；
3. **回复信定位声明独立可核对**：引擎解析回复信，抽取全部 E# 引用、引号引文（≥8 字）与 P###/SEC#/第 N 行坐标，逐项对照修订稿核验；任何"声称改了但定位不到"的声明列入 unresolvable_claims 并 exit 1，从机制上保证"回复信中的每一处定位都能在指定版本稿件中被独立核对"；
4. **模糊锚预警与失效锚标注**：method 以 fuzzy 开头的操作单独列出"锚点为模糊匹配，人工复核定位"；基线行号找不到的锚点如实标注"锚点已由改写消除"并附相似度，新增段落按规范落到锚段坐标——定位精度问题全部显式化，不藏在表里。

平台自动加载时无需手工操作；独立复用见 [docs/USAGE.md](docs/USAGE.md)。方法、边界与红线见 [SKILL.md](SKILL.md) 与 references/。


## 依赖与限制

Python 3.8+ 标准库；PDF 材料可选依赖 pdftotext（缺失时降级并记录）。只修订输入中实际提供的基线；不补做实验、不编造数据，未到位证据一律占位 + 清单 + 人工确认。
