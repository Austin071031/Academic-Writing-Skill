# 审稿回复与论文修改 Skill · v1.0.1 逐条回应决策台账

玻尔产品周赛第四期「审稿回复与论文修改」参赛作品（方向二：逐条回应，含语气控制）。

## 这是什么

一个可被 Agent 调用的 Skill：读入基线稿件 + 审稿意见清单，完成锚点编辑真实落稿，并由**结构化决策台账自动生成逐条回复信**（审稿人→意见→子要求三级，每条含决策+回应+修改指涉 E#+证据指涉 EV#），再经**答非所问检测**与**四档语气审计**把关，交付可核验、语气可控的返修包。

## 与基础 Agent 的差异（创新点）

1. **回复信由台账自动生成，不临场写**：信件内容全部来自 dispositions/edit_report/evidence_checklist 结构化数据，自动带 E# 应用状态与修订稿行号、EV# 证据状态；引用失败锚点自动标 ⚠ 并列入问题清单——基础 Agent 手写回复信时漏项、虚报"已修改"是高发问题，本机制从结构上杜绝。
2. **答非所问检测**：按子要求 action_kind（要数据/要删除/要格式/要回答）逐条核验回应是否对症（要数据必须引 EV# 或写明待补，提问必须含直接回答），这是基础 Agent 不自查的盲区。
3. **决策-语气一致性强制**：不采纳必须 ≥40 字含依据词且语气为澄清/礼貌反驳/申诉；采纳却无修改、无证据、无理由的判为"空洞接受"——防止"嘴上采纳、实际没改"。
4. **四档语气控制 + 红线扫描**：接受/澄清/礼貌反驳/申诉句式库外置为规则文档；对回复信全文扫描冒犯（"荒谬""审稿人误解了"）、过度承诺（"保证""一定会"）、无原则顺从（"完全同意您的所有意见"）三类红线并逐条给改写建议，FAIL 即 exit 1。

## 快速开始

平台自动加载时无需手工操作；独立复用见 [docs/USAGE.md](docs/USAGE.md)。方法、边界与红线见 [SKILL.md](SKILL.md) 与 references/。


## 依赖与限制

Python 3.8+ 标准库；PDF 材料可选依赖 pdftotext（缺失时降级并记录）。只修订输入中实际提供的基线；不补做实验、不编造数据，未到位证据一律【待补】占位 + 清单 + 人工确认。

## 与 v1.0.0 的关系

v1.0.0 主攻"意见拆解与覆盖台账"（解决答得全）；v1.0.1 复用同一共享核心，主攻"逐条回应决策台账"（解决回应质量与语气），两版可独立使用，也可串联（先拆解后回应）。
