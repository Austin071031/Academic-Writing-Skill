# 逐条回应规则：决策分类法、四档语气句式库、答非所问判据

本文件是 response_engine.py 的规则外置说明；引擎词表与本文件保持同步，改动任一侧须同步另一侧。

## 1. 决策分类法（每个子要求必选其一）

| 决策 | 定义 | 必填配套 |
|-|-|-|
| 采纳 | 完全接受意见并已（或将按占位）落实修改 | edit_ops 非空（指向真实 applied 的 E#），或 evidence + 理由说明 |
| 部分采纳 | 一部分可落实、一部分无法在本环境完成或需商榷 | edit_ops + evidence（EV#）+ response 写明哪部分待补、为什么 |
| 不采纳 | 有充分学术理由不接受（含意见与基线事实不符） | response ≥40 字、含依据词（因为/由于/依据/基线/原文）、引基线锚点（P###）或文献为据；tone 取 澄清/礼貌反驳/申诉 |

禁止项：决策空白；"已认真阅读并修改"式无指涉回应；采纳但引用 failed 锚点的 op（generate 会标 ⚠ 示众）。

## 2. 语气四档（tone 字段）

| 档位 | 适用 | 语气要点 |
|-|-|-|
| 接受 | 意见成立、已落实 | 先致谢、直接说明做了什么（引 E# 行号），有边界的不夸口 |
| 澄清 | 意见源于表述不清，非原则分歧 | 承认表述引起歧义，说明本意，补一句澄清文本（E#） |
| 礼貌反驳 | 意见与基线事实/领域共识不符 | 致谢并复述对方观点→引基线原文（P###）或文献为据→说明保留理由→（可选）补澄清句防后续误读 |
| 申诉 | 意见超出论文范围或要求不可行 | 说明范围边界与可行性限制，给出可提供的替代（如补充说明、占位待补） |

## 3. 四档句式库（可直接套用，〈〉内替换）

**接受**
- 感谢审稿人的建议。我们已按意见在〈章节〉补充/修改了〈内容〉（E#，修订稿第 N 行）。
- 同意该意见。已〈动作〉（E#）；其中〈超出可得数据的部分〉以【待补：…】占位，列入证据清单 EV#，到位后填入，不视为已完成。

**澄清**
- 感谢审稿人指出此处表述不清。我们的本意是〈本意〉；为避免歧义，已在〈章节〉补充一句澄清（E#）。

**礼貌反驳**
- 感谢审稿人提出的观点。经核对，基线〈P0##〉原文「……」表明〈事实〉，因此我们认为〈结论〉；为避免歧义，已在〈章节〉补充澄清（E#）。
- 我们理解审稿人的关切，但依据〈基线原文/文献〉，〈理由（因为/由于…）〉，故保留现有表述；已在回复中说明依据。

**申诉**
- 感谢审稿人的建议。〈所要求事项〉超出本文的研究范围/当前条件（因为〈理由〉），难以在本次返修中完成；我们已在〈章节〉补充说明（E#），并将〈可行替代〉列入待办（EV#）。

## 4. 答非所问判据（audit 的 off_topic 检查，按 action_kind）

| action_kind | 判定"对症"的必要条件（response 文本） | 典型答非所问 |
|-|-|-|
| add_experiment / add_data / add_citation / reanalysis | 含 EV# 引用，或含"待补/无法/补做"字样 | 只致谢不引证据、把待补说成已补 |
| delete | 含"删"字，或 edit_ops 中有 action=delete 的 op | 说"已修改"却未说明删除 |
| format | 含格式类词（格式/缩写/全称/简称/单位/排版/字体/编号/图表/标点/大小写），或引用任意 op | 答非所问地讨论实验细节 |
| question | 含直接回答信号词（因为/由于/是由于/原因是/原因在于/is because） | 绕开问题不回答原因 |
| rewrite / other | 不强制（由 verify_revision 的空话检查兜底：≥20 字且含可核查指涉） | — |

## 5. 决策-语气一致性判据（audit 的 tone_consistency 检查）

1. decision=不采纳 → tone 必须 ∈ {澄清, 礼貌反驳, 申诉}；response ≥40 字且含依据词（因为/由于/依据/基线/原文）。违反分别记入 tone_mismatch / weak_reject。
2. decision=采纳/部分采纳 → edit_ops、evidence、理由词三者至少其一，否则记 hollow_accept（空洞接受）。

## 6. 语气红线（audit 的 tone_redlines 检查，扫描回复信全文）

| 类别 | 命中词表 | 改写方向 |
|-|-|-|
| 冒犯性 | 荒谬 / 毫无道理 / 审稿人误解了 / 明显错误 / nonsense | 礼貌反驳句式（第 3 节）：致谢+引据+说明，不评价对方水平 |
| 过度承诺 | 保证 / 一定会 / 彻底解决 / guarantee / definitely will | 有边界的接受句式：已做 X（E#），受〈条件〉限制，Y 以【待补】占位 |
| 无原则顺从 | 完全同意您的所有意见 | 逐条对应句式：同意的引 E#，保留的给依据，不打包顺从 |

命中即 FAIL，须按建议句式改写后重跑 audit。
