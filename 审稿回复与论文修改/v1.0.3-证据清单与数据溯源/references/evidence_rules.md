# 证据规则（evidence_rules）

本文件定义"证据补充"方向的判定标准：四类证据需求、三档到位状态、替代说明句式、数字溯源规则。evidence_engine.py 的初判逻辑与 Agent 的终判复核都以此为准。

## 1. 四类证据需求（demand）

由 comments.json 中子要求的 `action_kind` 映射；Agent 复核 comments.json 时应先修正 action_kind，再确认 needs_evidence。

| action_kind | demand | 定义 | 典型意见措辞 |
|-|-|-|-|
| add_experiment | 补实验 | 需要新的实验/测试/表征才能回答 | "补充循环伏安测试""建议做倍率性能实验" |
| add_data | 补数据 | 需要基线中不存在的原始数据或统计数据 | "补充误差棒与重复次数""给出粒径分布数据" |
| add_citation | 补文献 | 需要引用基线参考文献列表之外的文献 | "引用近三年文献""与已报道工作定量对比" |
| reanalysis | 重做分析 | 需要用原始数据/代码重新计算或换方法分析 | "建议用恒电位间歇滴定重新分析""应做统计检验" |
| 其他（rewrite/format/other 但 needs_evidence=true） | 其他证据 | 不属于上四类但需要外部材料支撑 | "更新图 1""提供样品照片" |

## 2. 三档到位状态（status）

| 状态 | 判据 | 交付要求 |
|-|-|-|
| 到位 | 证据已真实写入修订稿：引用的 op 已 applied 且 new_text 无【待补】，且证据内容确实在基线/材料内可查证 | 回复信引用 EV# 与落稿位置；人工复核数值与出处一致 |
| 部分到位 | 修改已落稿但含【待补：…】占位（证据本体材料外） | 占位写清"缺什么、向谁要"；回复信说明状态；列入证据清单 |
| 无法补做 | 无任何落稿修改可承载该证据，或条件根本不存在 | 回复信必须给替代说明（见第 3 节）；列入证据清单与 manual_confirmations；不得编造 |

**初判与终判**：脚本按上表机械初判（只依据 op 应用状态与占位标记），无法判断"证据内容是否真实支撑论断"——这是 Agent 终判的职责。典型修正：初判"到位"但落稿文本只是复述意见而无真实数据 → 终判降级为"部分到位"并补占位。

## 3. 替代说明写法（无法补做时的句式）

替代说明 = 原因（为什么不能补）+ 补救（等效佐证或局限声明）+ 去向（列入清单与人工确认）。三类典型原因各给一句式，可直接改写进回复信：

**实验条件不再可得**：
> 感谢审稿人的建议。该实验需在〈设备/条件〉下完成，目前〈样品已耗尽 / 装置已拆除 / 测试周期超出返修期限〉，实验条件已不存在，无法在返修期内补做。作为等效佐证，我们〈引用了相近工艺条件的已发表数据 / 补充了现有数据的支持性分析〉，并在修订稿〈章节〉加入局限声明："……"。

**原始数据未采集**：
> 该数据在实验阶段未采集（原始记录中无〈数据项〉），无法事后补测。我们已在修订稿〈章节〉补充定性说明与局限声明；后续工作将按审稿人建议采集该数据。【待补：〈数据项〉，待作者补测后回填】

**文献无法核验**：
> 本返修环境无法联网核验文献，为避免误引，我们不直接补写未经核实的文献条目。建议检索关键词：〈关键词组合〉，预期可支撑〈论断方向〉；请作者核实后以真实文献替换【待补：〈文献主题〉】占位。我们承诺不编造文献条目。

禁止的写法：冒称"已补充实验数据如下"并编造数值；冒称"已查阅文献确认"；用"由于篇幅原因从略"搪塞需要证据的意见。

## 4. 数字溯源规则（provenance）

### 4.1 溯源对象

- `/app/output/response_letter.md` 全部行（按行定位 L#）；
- edit_plan 中所有 **applied** op 的 new_text（有 edit_report 时以 applied 为准）。

### 4.2 数字抽取

正则：整数/小数/百分数；两侧紧邻 ASCII 字母/数字/下划线的不算（排除 R1、E3、P005、EV2 等编号）；`## Reviewer 1` 等标题中的审稿人序号跳过；百分号前空白归一（"78 %"≡"78%"）。检索比对时同样带边界（防止 1450 命中 45、1.5 命中 5）。

### 4.3 四档判定（优先级从高到低）

| 判定 | 条件 | 记录 |
|-|-|-|
| 溯源成功 | 数字在基线全文可找到 | `baseline P### L<行号>`（P### 来自 structure.json，行号来自基线原文件） |
| 意见给出 | 基线没有，但意见原文（sub text / raw_text）有 | `comments <sub_id>`；**不算未核实**，无需人工确认 |
| 待补 | 以上皆非，但 ±20 字邻域内有【待补】标记或数字本身在占位括号内 | 占位待回填；不重复进人工确认 |
| 未核实 | 以上皆非 | 写入 work/manual_confirmations.json（含上下文 ±20 字）；exit=2 告警 |

### 4.4 处置纪律

- 未核实数字只有两条出路：作者确认其出处（人工确认条目留档），或改为【待补：…】占位/删除后重跑 provenance 至 exit=0；
- exit=2 不阻断流程（数字可能确属作者掌握），但 status=success 要求全部未核实数字已在 manual_confirmations 留档且回复信如实披露；
- 溯源只核对"数字是否出现过"，不核对"语义是否用对"——语义复核仍是 Agent 职责（如基线 78% 是库仑效率，不得挪作保持率）。

## 5. 证据-论断映射（evidence_map.json）

provenance 阶段为每条 EV × 关联子要求的 response 自动生成条目：

```json
[{"claim": "<子要求的回复要点>", "source": "EV1（baseline P005b；证据本体材料外，待作者补充）",
  "kind": "evidence | placeholder"}]
```

kind 映射：EV 状态=到位 → evidence；部分到位/无法补做 → placeholder。意见直接给出的论断可手工补 kind=comment 的条目（source=comments sub_id）。
