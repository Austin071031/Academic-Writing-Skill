# 基础 Agent 典型失败模式与本技能对策（研究基础节）

## 失败模式 1：拟开展内容写成已完成体

基础 Agent 为增强说服力，把"拟建平台、拟开展验证"写成"已建立平台、已完成验证"，
属于事实性错误中最严重的一类——评审函评阶段即可能被判为科研诚信问题。

**对策**：体貌机检规则 2——段落带〔拟〕标记但体貌判 completed → high。
〔拟〕标记强制写作时显式声明拟态，体貌信号词表（已/了/发表/获得/建立…）逐段扫描。

## 失败模式 2：成果断言无出处

"申请人已发表高水平论文多篇、已获授权专利数项"式笼统罗列，无刊名/专利号/项目号，
评审无法核验，也不满足"查得到"的要求。

**对策**：规则 4——含 论文/专利/项目/平台/奖项/发表/授权/结题 任一信号且无〔F〕标记 → high；
fact_ledger 的 pub_mention 类型已抽取期刊名、DOI、专利号（ZL…）、基金批准号，
Agent 直接取用即可逐条锚定。

## 失败模式 3：罗列简历、不谈与本研究的关系

把申请人全部成果按时间倒序堆进研究基础节，与本课题的研究内容、技术路线无对应关系，
评审读完仍不知道"为什么这个团队能做这个项目"。

**对策**：证据链三列结构强制"能力—证据—与本研究关系"；seed 机选行为
prior_work 材料段落提供关系填写素材；规则 5 检查 relation_to_project 非空；
写作句式判据要求关系列落到具体研究内容/技术路线条目。

## 失败模式 4：平台条件空转

"依托国家重点实验室"式一句话带过，不说明平台有哪些具体条件（设备/规模/工艺能力）、
这些条件如何支撑本课题的关键实验，可行性论证流于形式。

**对策**：规则 6 全节可行性信号检查（可行/条件/保障/平台/团队/基础）；
seed 的 PRIOR_SIGNALS（申请人/本团队/平台/实验室）保证平台条件段落进入证据链候选；
references/feasibility_method.md 给出"平台条件→支撑实验"的判据句式。

## 失败模式 5：已完成成果写成拟开展体

反向错误：申请人确有已发表论文，草稿却写成"拟发表高水平论文"，
自我贬低前期积累，削弱"为什么是我们"。

**对策**：规则 3——锚定成果类〔F〕（type=pub_mention/number 且来源 prior_work）的段落体貌判
planned → medium。轻度者（措辞含"拟"但实为完成体）提示改写为完成体。

## 失败模式 6：超时只交付半成品

900 秒预算内通读材料+写七节稿容易超时空手。

**对策**：init_result 骨架先行；sections 逐节落盘；draft_builder 随时可组装部分结果；
证据链 seed 把研究基础节的素材初筛前置，压缩 Agent 通读时间；预算兜底规则写进 SKILL.md 第 7 步。
