# 研究基础证据链方法判据（feasibility_engine 判定规则）

## 证据链三列

研究基础节的每一条基础都必须填齐三列，缺一即证据链不完整：

| 列 | 回答的问题 | 来源与判据 | 机检 |
|-|-|-|-|
| 能力（capability） | 我们会什么 | prior_work 材料中已完成的成果/平台/团队事实，机选为段落前 30 字短语 | seed 自动生成，Agent 审定改写 |
| 证据（evidence_fids + sources） | 凭什么说会 | 台账 FID（type=pub_mention/number 等），来源坐标 file_id+pid 可回溯 | audit 规则 3/4 核对锚定 |
| 与本研究关系（relation_to_project） | 支撑本课题哪一步 | Agent 手工填写："该能力/证据直接支撑研究内容（X）/技术路线第 N 步/目标 X" | audit 规则 5 检查非空 |

写作句式（每条基础）：「申请人已<完成成果>〔Fxxxx〕，具备<X 能力>，将支撑本研究<Y>。」
关系列的判据：能具体到研究内容/技术路线条目、与本课题瓶颈呼应才算合格；
"为本研究提供有力支撑"一类空话视为不合格，Agent 第 6 步须改写。

## 已完成/拟开展体貌词表（grant_utils.aspect_classify 与引擎共用）

- **已完成信号**：已、了、发表、获得、建立、掌握、完成、实现、授权、结题、见刊。
- **拟开展信号**：拟、将、计划、预期、有望、准备、旨、待。
- 体貌判定在**剥除〔F〕〔拟〕〔确认〕标记后**的段落体上进行。

### 判例

| 情形 | 例句（已剥标记） | 判定 | audit 规则 |
|-|-|-|-|
| 已完成成果，带〔F〕 | 已获授权发明专利 ZL202210123456.7 | completed ✓ | 无 finding |
| 拟开展内容，带〔拟〕 | 本课题将在已建成的中试线上完成放大验证 | mixed（已+将）→ 见误报 2 | 不命中（混合体），建议拆段 |
| 拟开展写成已完成 | 本课题下一阶段已完成放大效率复测〔拟〕 | completed + 〔拟〕 → high | 规则 2 aspect_violation_planned_as_done |
| 已完成写成拟开展 | 申请人拟将相关成果整理投稿至 Joule 期刊〔F0034〕（材料记载已见刊） | planned + 成果类〔F〕 → medium | 规则 3 aspect_violation_done_as_planned |
| 无信号的中性表述 | 平台配有原位表征设备 | neutral | 体貌规则不命中，按锚定规则检查 |

## 成果断言锚定规则（audit 规则 4，severity=high）

段落含 论文、专利、项目、平台、奖项、发表、授权、结题 任一信号词，
**且无任一〔F〕标记** → unsourced_achievement。
判据：成果类断言必须逐条指向台账中 type=pub_mention（期刊名/DOI/基金号/专利号）或
number（规模/年限/台套数）的事实；同一行写多条成果但只标一个〔F〕，由第 12 步 Agent 复核补齐。

规则 3 的成果类〔F〕定义：台账 type ∈ {pub_mention, number} **且来源文件 role_guess=prior_work**——
避免 paper 角色材料中的外部数字被误当申请人成果。

## 证据链完整性（audit 规则 5）

- `work/evidence_chain.json` 不存在（无论 seed 是否存在）→ low 提示「未生成审定版」。
- 存在 → 逐行检查 relation_to_project 非空，空行 → medium（附行号与能力短语）。

## 可行性信号（audit 规则 6，severity=low）

全节（剥标记后）无 可行、条件、保障、平台、团队、基础 任一信号词 → feasibility_missing。
判据：研究基础节至少覆盖可行性论证的一个支柱——平台条件 / 团队分工 / 技术保障，
一句话即可，但完全缺失意味着该节只剩成果罗列。

## 误报来源与处置

1. **〔拟〕段落含"已"的混合句**："本课题拟在已建成的中试线上完成放大验证"
   判 mixed 不命中规则 2（设计上放宽），但语义可读性差——建议拆为
   "已建立中试线〔Fxxxx〕／拟在其上完成放大验证〔拟〕"两句。
2. **平台/团队等信号词出现在条件句而非断言**（"平台条件尚不具备"）仍命中规则 4：
   有成果信号无〔F〕。处置：该句若属材料事实，从材料找锚点补〔F〕；若属申请人自评，标〔确认〕。
3. **prior_work 文件角色误判**（指南判成 prior_work）：指南中的"平台/团队"表述会进 seed 行，
   Agent 第 6 步按真实角色删除即可；audit 规则 3 因要求来源 prior_work 会一并降低误判面。
4. **"已"在非完成义语境**（"已知机制尚不清楚"）：与〔拟〕同段才影响判定；
   纯现状描述段不影响研究基础节审计。
5. **成果〔F〕标记引用 paper 角色数字**（如复用台账中论文性能数字）：type=number 但来源非
   prior_work，不计成果类〔F〕，规则 3 不命中；是否合规由第 12 步按"断言主体是申请人还是文献"复核。
