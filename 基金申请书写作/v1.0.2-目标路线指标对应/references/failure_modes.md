# 基础 Agent 典型失败模式与本技能对策

## 失败模式 1：条目数不一致（目标三个、路线两条）

基础 Agent 分节独立生成，研究目标列三条，技术路线只写两条（常漏掉放大/应用类目标），
研究内容两条半——评审一眼看出"目标与路线对不上"，是一致性硬伤中最致命的一类。

**对策**：第 6 步先定条目数 n 再动笔；第 8 步后重跑 `alignment_engine.py seed`
打印四节计数自查；audit 的 count_mismatch（high）写明"目标 3 条、内容 2 条"
式事实，定位到具体差距，修订后重跑清零。

## 失败模式 2：孤儿指标（考核指标另说一套）

基础 Agent 把考核指标写成通用套话（"发表高水平论文 3-5 篇、申请专利 2 项"），
与三条研究目标毫无字面或编号关联，指标无法回溯到任何目标。

**对策**：覆盖规则要求每条指标 ≥1 个目标可回溯（orphan_metric，medium）；
写作判据要求"指标X：对应目标X，……"句式并标〔拟〕；指标值必须与目标同源，
不许另起炉灶。

## 失败模式 3：技术路线与研究内容脱节

技术路线写成方法学流水账（"首先合成样品，然后表征，最后分析数据"），
不指向任何具体研究内容；或只覆盖部分研究内容，剩余内容无路线支撑。

**对策**：覆盖规则要求每条内容 ≥1 条路线对应（orphan_content，medium）；
写作判据要求"步骤X：针对研究内容（X）……"句式，触发编号互引（ref）规则
直接建立对应；alignment_table.md 以目标为锚展示全链对应，断链一目了然。

## 失败模式 4：编号体例混乱

同一篇申请书里目标用"（1）"、内容用"第一/第二"、路线无编号、指标用"-"列表，
甚至编号连写不换行；人工阅读和机器核查都无法对齐条目。

**对策**：引擎支持 1./（1）/（一）/①/目标一/步骤一/第一条 等多种行首体例，
但混用与连写会记 note（"疑似编号未换行或体例混用"）；无编号节按段落整体切条
并记 note；SKILL.md 推荐四节统一体例：目标一/（一）/步骤一/指标一。

## 失败模式 5：目标口径漂移（目标与内容同名不同义）

基础 Agent 各节措辞各自发挥：目标写"揭示机制"，内容写"开发工艺"，字面与语义
都对不上，对应关系靠读者脑补。

**对策**：跨节相似度矩阵（trigram ≥ 0.12）机检字面呼应；同义改写导致的低相似
孤儿是候选误报，Agent 复核驳回或改写条目共享关键术语；写作判据要求内容条目
开头显式呼应目标编号。

## 失败模式 6：缺考核指标节

任务要求考核指标，基础 Agent 常把指标揉进研究目标段尾一句话带过，或干脆不写。

**对策**：missing_section（high）识别无 考核指标/预期成果 element 且无指标信号
段落的草稿；SKILL.md 异常表给出补写路径（`NN_考核指标.md`，指标逐条回溯目标）。

## 失败模式 7：超时只交付半成品

900 秒预算内通读长材料+写多节稿容易超时空手。

**对策**：init_result 骨架先行；sections 逐节落盘；draft_builder 随时可组装
部分结果；预算兜底规则写进 SKILL.md 第 7 步（请求过半跳到第 8 步交付 partial）。
