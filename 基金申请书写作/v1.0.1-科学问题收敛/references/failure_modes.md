# 基础 Agent 典型失败模式与本技能对策（科学问题）

## 失败模式 1：问题过大（写成领域工程而非问题）

基础 Agent 常把科学问题写成「系统研究界面工程的各个方面，全面揭示其机理」：
没有问句、没有变量、没有边界，等于宣告"什么都做"，评审无法判断聚焦点。

**对策**：scope_too_broad 对系统研究/全面揭示/各个方面/诸方面/全方位/彻底解决
逐段命中（high）；改写判据：把过大表述收敛为"哪一个具体机制/定量关系尚未阐明"的问句。

## 失败模式 2：口号式问题（排比问句堆砌）

「如何推动科技进步？如何解决能源危机？如何服务国家战略？」——问句形式正确但
对象空洞、不可回答，实为研究意义口号的问句化。

**对策**：问题候选只从材料 gap/未知信号词（尚不清楚/机制不明/亟待…）机选，
Agent 审定的问题必须锚定材料中的具体 gap 与〔F〕证据；method_misaligned
进一步抓"问题与研究目标/路线两套话"。

## 失败模式 3：问题与研究目标、技术路线错位

科学问题写界面机制，研究目标写放大制备，技术路线写设备建设——三节各说各话，
评审一眼看出"目标不是为问题服务"。

**对策**：method_misaligned：问题节与研究目标、技术路线节 trigram 相似度
双低于 0.05 → medium；写作判据要求问题关键词（对象/机制/方法）三节复现。

## 失败模式 4：无边界声明

问题节写完"我们研究 X"就结束，不说不涉及什么；评审据此判断"范围不可控、风险大"。

**对策**：no_boundary：全节无 不涉及/边界/限定/聚焦/仅限于/排除 即 medium；
写作模板强制「聚焦于…，不涉及…，限定于…」边界句。

## 失败模式 5：数量失衡（0 个或 5+ 个问题）

写"五大科学问题"把整份申请书摊薄，或一个问句都没有只写研究意义段落。

**对策**：question_count 识别"？/？"问句与编号条目取较大者，>4 → medium
「问题数量过多，未收敛」；0 个时第 6 步 Agent 从候选收敛 1-3 个核心问题。

## 失败模式 6：无子问题分解

核心问题悬空：写了一个大问句，但没有（1）（2）或其一/其二把它落到可执行的研究内容，
后续章节无法承接。

**对策**：no_decomposition：核心问题存在但全节无分解标记 → medium；
问题树写法（references/question_method.md）要求核心问题→2-4 个子问题→任务。

## 失败模式 7：超时只交付半成品

900 秒预算内通读长材料+写七节稿容易超时空手。

**对策**：init_result 骨架先行；sections 逐节落盘；draft_builder 随时可组装
部分结果；预算兜底规则写进 SKILL.md 第 7 步（请求过半跳 partial）。
