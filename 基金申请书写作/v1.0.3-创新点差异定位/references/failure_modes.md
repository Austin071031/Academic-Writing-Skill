# 基础 Agent 典型失败模式与本技能对策（创新点节）

## 失败模式 1：「首次体」——用时间优先权代替差异

基础 Agent 常写「本研究首次提出…」「首次将…应用于…」，把创新性寄托在无法核验的
优先权声明上。评审无法从材料判断"是否首次"，此类表述等于没有信息。

**对策**：BANNED_MODIFIERS 黑名单 high 级命中「首次」；替换句式库第 1 组把
「首次提出 X」改写为「提出 X，不同于已有工作 Y〔F〕」；「首次提出」不计入
"新在哪里"维度，防止换汤不换药。

## 失败模式 2：「领先体」——用水平表态代替指标差异

「达到国际领先水平」「国际先进」「世界领先」「领跑」「填补国内外空白」是
最常见的水准类空话，既没有对比对象也没有可核验指标。

**对策**：黑名单 high 命中 + 替换指令（删除表态 → 改为 已有工作 X 做到…〔F〕，
本课题相比 X 在指标/机制上…）；替换句式库第 2/3/4/7/8 组给出可直接套用的
指标化改写（效率值、保持率、老化数据均须带〔F〕来自台账）。

## 失败模式 3：无对比对象——创新点悬浮在半空

通篇「本课题提出新策略…」却不提任何已有工作，读者不知道"新"是相对谁而言。

**对策**：no_baseline_anchor（medium）逐条检查〔F〕指向 citation/pub_mention 类
事实或 已有工作/现有研究/文献 等对比对象表述；innovation_engine.py seed 预先
从 paper 角色材料机选代表性已有工作锚点（innovation_seed.json），写作时逐条对比。

## 失败模式 4：创新与内容两张皮

创新点节写得天花乱坠，研究内容/技术路线里找不到对应任务；或把研究内容
复述一遍就当创新点，没有任何差异表述。

**对策**：no_difference_statement（medium）逐条检查 不同于/区别于/相比/优于/
而非/改为/突破了/克服了/解决了/避免了；写作判据要求每条创新点的差异对象
与研究内容条目呼应（Agent 第 7 步按要素逐条对应撰写）。

## 失败模式 5：堆形容词代替三维论证

「意义重大、特色鲜明、创新性强」式自我评价，答不上 新在哪里/为什么难/凭什么做得成。

**对策**：three_dim_incomplete（medium）全节检查三维关键词覆盖，缺哪一维 finding
写明哪一维并给补写指令；references/innovation_method.md 三维判据表给出每维
通过信号与常见缺陷。

## 失败模式 6：超时只交付半成品

900 秒预算内通读长材料+写七节稿容易超时空手。

**对策**：init_result 骨架先行；sections 逐节落盘；draft_builder 随时可组装
部分结果；预算兜底规则写进 SKILL.md 第 7 步。
