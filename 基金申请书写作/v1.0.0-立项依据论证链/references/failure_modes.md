# 基础 Agent 典型失败模式与本技能对策

## 失败模式 1：口号堆叠代替必要性论证

基础 Agent 常把立项依据写成「意义重大、国家战略需求、备受关注」的排比，
没有任何可核验事实。评审无法判断"为什么值得做、为什么现在必须做"。

**对策**：SLOGAN_WORDS 机检 + 改写判据（事实〔F〕→因此有必要），
链环完整性检查强制 现状/瓶颈/我们 三段齐备。

## 失败模式 2：现状综述无出处

「近年来，国内外学者开展了大量研究」式综述，无一篇具体文献或数据，
属于无法核验的笼统表述。

**对策**：STATE_WORDS 命中且无引用/数字类〔F〕锚定 → state_claim_unanchored；
事实台账要求每个数字/引用逐条登记来源坐标（file_id + pid）。

## 失败模式 3：材料外数字与臆造文献

基础 Agent 凭训练记忆写入「效率已达 26.7%」「Nature 2023 报道」等材料中
不存在的事实，与案例材料冲突时直接造成正确性失分。

**对策**：source_audit 逐段比对草稿数字/引用与台账值集合，材料外数字
severity=high；〔F〕标记指向不存在条目由 draft_builder 拦截。

## 失败模式 4：前期成果与项目脱节

罗列申请人全部论文但与本课题瓶颈无关，「为什么是我们」不成立。

**对策**：我们槽候选只从 prior_work 角色材料机选；写作判据要求每条成果
与瓶颈一一呼应；gap_question_disjoint 检查瓶颈与科学问题衔接。

## 失败模式 5：已完成与拟开展混写

把「拟建设备」写成「已建立平台」，属于事实性错误中最严重的一类。

**对策**：证据标记语法强制〔拟〕；grant_utils.aspect_classify 提供体貌信号
（已完成：已/了/发表/获得/建立；拟开展：拟/将/计划/预期）供 Agent 写作时自查。

## 失败模式 6：超时只交付半成品

900 秒预算内通读长材料+写七节稿容易超时空手。

**对策**：init_result 骨架先行；sections 逐节落盘；draft_builder 随时可组装
部分结果；预算兜底规则写进 SKILL.md 第 7 步。
