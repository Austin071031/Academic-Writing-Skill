# 失败模式：基础 Agent（无本 Skill）在编号更新任务上的典型翻车

以下模式来自对"顺序编码制稿件编辑"任务的基础 Agent 行为归纳，正是本 Skill 要消除的
风险；每条给出本 Skill 的对应防线。

## FM-1 手改正文、忘改文末列表（或反之）

- **现象**：Agent 把正文里 `[5]` 改成 `[4]`，但文末列表仍是 5 条或旧序；评审一核对
  即发现正文引用与列表错位。
- **成因**：两处状态在 Agent 上下文里是分离的，长文档下必然漏一处（图注/表注/附录
  更容易漏）。
- **本 Skill 防线**：单一事实源——Agent 只写 edit_ops；正文与列表由同一份 mapping
  一次性重排+重建，物理上不可能只改一处。终检 `max==列表条数` 兜底。

## FM-2 删除条目后留缺口/重号

- **现象**：删掉列表第 3 条后列表变 `[1][2][4][5]`；或正文出现两个 `[3]` 指向不同
  文献。
- **成因**：Agent 按"所见即所得"逐处替换数字，不做全局重排。
- **本 Skill 防线**：mapping 是 旧号→新号 的全量双射（删除=null），引擎对全文逐号
  替换后重新压缩区间；`1..N 无缺口` 终检直接拦截。

## FM-3 图表注/附录编号不同步

- **现象**：正文改顺了，"图 2 数据来自文献[7]"里的 7 还是旧号（该文献已变成 5）。
- **成因**：基础 Agent 只扫正文段落，图注表注被视为"装饰文本"。
- **本 Skill 防线**：parse_manuscript 按 kind 分类（figure_note/table_note/appendix/
  footnote），renumber 对**所有** kind 段落统一执行；悬空检测同样覆盖这些 kind。

## FM-4 区间引用改一半

- **现象**：`[2-5]` 删了 3 号后变成 `[2-5]`（未动）或手写 `[2-4]`（但实际应为 `[2,4-5]`）。
- **成因**：区间是压缩表示，Agent 需要心算展开-映射-再压缩，出错率极高。
- **本 Skill 防线**：expand→逐号映射→compress 全自动（`[1-5]` 删 3 → `[1-2,4-5]`）。

## FM-5 删除仍被引用的条目后"假装没事"

- **现象**：删掉文献后正文仍出现指向它的编号，成为悬空引用；Agent 不报告直接交付。
- **本 Skill 防线**：删除前的悬空检测 + FAIL + 段落级清单；处置闭环（改写→重跑→PASS）
  写入 SKILL.md 主流程，且 validate 前 status 不得为 success。

## FM-6 多位置引用改漏（一句多引/多处引用同一条）

- **现象**：同一文献在 6 处被引，Agent 改了 5 处。
- **本 Skill 防线**：正则全量替换基于 mapping，与出现次数无关；`1..N 无缺口` 终检使
  漏改必然暴露（漏改的旧号会变成缺口或越界）。

## FM-7 著者-出版年稿件强行"重排"

- **现象**：对 (作者, 年) 稿件执行数字重排，破坏正文标记。
- **本 Skill 防线**：样式嗅探（inspect_case + manuscript styles_detected）分流；
  author-year 模式只查排序与 stale，报告中明确说明未重排。

## FM-8 幻觉性"顺手修正"

- **现象**：Agent 在改编号时"顺便补全"了某条文献的卷期页或 DOI（实为编造）。
- **本 Skill 防线**：列表文本只能来自输入文献库/稿件自带列表（或 reference_list.json
  原文），Agent 无写列表的通道；诚实红线 1 明令禁止臆造元数据。

## 对照速查

| 失败模式 | 本 Skill 防线 | 终检项 |
|---|---|---|
| FM-1 两处不同步 | 单一 mapping 双写 | max==列表条数 |
| FM-2 缺口/重号 | 全量双射重排 | 无缺口 |
| FM-3 图表注漏改 | 全 kind 重排 | 样式一致+max |
| FM-4 区间改一半 | expand→map→compress | 无缺口 |
| FM-5 悬空不报告 | 删除前检测+FAIL | 悬空为空 |
| FM-6 多位置漏改 | 次数无关替换 | 无缺口/越界 |
| FM-7 错配样式 | 样式嗅探分流 | author-year 分支说明 |
| FM-8 幻觉补全 | 列表写通道封闭 | 出处字段可回溯 |
