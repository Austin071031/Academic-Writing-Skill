# edit_ops.json 操作 Schema 与例子

Agent 从任务书识别编辑操作后写入 `work/edit_ops.json`。引擎按**列表顺序依次执行**，
每个操作作用于"当前列表状态"（前一个操作的结果之上）。

## Schema

```json
[
  {"op": "delete",          // 从文末列表删除一条
   "ref_id": "R007",        // 定位：R00X=条目身份（推荐）；纯数字 "7"=当前列表第 7 位
   "note": "任务书出处与理由（必填，审计用）"},

  {"op": "reorder",         // 调序，两种形式
   "ref_id": "R003", "to": 1,          // 形式A：单条移动到第 to 位（1 起；to 缺省=末尾）
   "ref_ids": ["R002","R001"],         // 形式B：子集全序——给出的条目按此相对顺序，
   "note": "..."},                      //   未给出的条目保持原相对顺序插在空位

  {"op": "insert_existing", // 把文献库中已有、但当前列表未收录的记录插入列表
   "ref_id": "R012",        // 必须是 library.json 中真实存在的 R00X
   "to": 3,                 // 插入位置（1 起；缺省=末尾）
   "note": "..."},

  {"op": "merge",           // 条目合并（如两章合并后发现同一文献两条）
   "ref_ids": ["R003", "R008"],  // 参与合并的一组
   "keep": "R003",               // 保留哪条（缺省=ref_ids 第一个）
   "note": "..."}                 // keep 以外的条目从列表删除（其编号=删除）
]
```

定位语义（重要）：`R00X` 按**条目身份**在当前列表中查找——前面操作改变了位置也能正确定位；
纯数字按**当前列表序号**（第 k 位）解释。两者混用是刻意设计：任务书说"删除第 3 条"用数字，
说"删除 R007/那篇 Oxford 专著"用身份。

## 20 个例子（含边界）

1. `{"op":"delete","ref_id":"R005","note":"撤稿"}` — 删除第 5 条。
2. `{"op":"delete","ref_id":"5","note":"任务书：删除第 5 条"}` — 等价（纯数字=当前序号）。
3. `{"op":"delete","ref_id":"R001"}` 后 `{"op":"delete","ref_id":"R001"}` — 第二次定位失败
   （已删），记入 ops_errors，不影响其余操作。
4. `{"op":"delete","ref_id":"R999"}` — 超出文献库范围，跳过并记录。
5. `{"op":"reorder","ref_id":"R003","to":1}` — R003 移到首位，其余相对顺序不变。
6. `{"op":"reorder","ref_id":"R001","to":99}` — to 越界时钳制到末尾。
7. `{"op":"reorder","ref_ids":["R006","R002"]}` — R006 排到 R002 前；其余条目保持相对序。
8. `{"op":"reorder","ref_ids":["R003","R002","R001"]}` — 前三条完全倒序。
9. `{"op":"reorder","ref_ids":["R002","R005"],"to":null}` — 形式B 不接受 to（忽略），不报错。
10. `{"op":"insert_existing","ref_id":"R012","to":2}` — 库中 R012（此前不在列表）插入第 2 位；
    正文可在插入后直接引用 `[12]`，引擎会把它重排为新号。
11. `{"op":"insert_existing","ref_id":"R003"}` — R003 已在列表 → 跳过并提示"用 reorder 调序"。
12. `{"op":"insert_existing","ref_id":"R020"}` 但库只有 15 条 → 超出范围，跳过并记录。
13. `{"op":"merge","ref_ids":["R003","R008"],"keep":"R003"}` — R008 删除、R003 保留原位次含义。
14. `{"op":"merge","ref_ids":["R003","R008"]}` — keep 缺省=ref_ids[0]=R003。
15. `{"op":"merge","ref_ids":["R003","R008"],"keep":"R008"}` — 保留 R008，删 R003（keep 任意指定）。
16. 删除后再 merge：`[{"op":"delete","ref_id":"R003"},{"op":"merge","ref_ids":["R005","R006"],"keep":"R005"}]`
    — 按顺序执行；keep 用 R00X 身份定位，不受先前删除导致的位移影响。
17. `{"op":"move","ref_id":"R001"}` — 非法 op，记入 ops_errors 并跳过。
18. `{}` 或 `"note"` 缺省 — op 缺失则跳过；note 缺失不报错但**不推荐**（审计缺出处）。
19. `[]`（空列表）— 恒等映射：引擎仍做全量不变量终检并输出报告，可用于"只体检不改号"。
20. `{"op":"delete","ref_id":"R004","note":"删"}` + `{"op":"insert_existing","ref_id":"R004"}`
    — 先删再插回同一记录：最终回到原位（等效恒等），合法但应在 note 中说明意图。

## 约束与失败行为

- ref_id 定位失败 / op 非法 / insert 越界：该操作跳过，`ops_errors` 记录原因，**不中断**其余操作。
- 所有删除产生的"删除后仍被正文引用"由引擎在重排前检测并列入悬空清单（见 chain_update.md）。
- 操作只影响**列表与编号**；正文句子改写永远是 Agent 的职责（改 manuscript.json 的
  text/cite_marks，不得改其中数字后冒充"已改完"——数字重排只属于引擎）。
