# 连锁更新规则

引擎（renumber_plan.py + cite_engine renumber）执行一次编号更新时，以下位置**全部同步**，
Agent 与评审可用此清单逐项核对：

## 1. 同步范围（所有 kind 段落）

| 位置 | 段落 kind | 处理 |
|---|---|---|
| 正文句中标记 | body / heading | 重排 |
| 图注（"图 1 …"） | figure_note | 重排 |
| 表注（"表 2 …"） | table_note | 重排 |
| 附录段落 | appendix | 重排 |
| 脚注/尾注段 | footnote / body（脚注行） | 重排 |
| 文末列表条目标签 | reference_list | 旧列表段整段废弃，由重建列表替换（防止旧编号残留） |

## 2. 标记形态规则

- **区间压缩**：`[1,2,3]` → `[1-3]`；`[2,3,4,6]` → `[2-4,6]`（压缩由 cite_engine
  的 compress_nums 完成，重排后自动重新压缩，不会输出松散连续号）。
- **区间展开**：`[1-3]` 视为 `{1,2,3}` 逐号映射；映射后重新压缩。删除区间内某号时
  只去掉该号：`[1-5]` 删 3 → `[1-2,4-5]`。
- **一句多引**：`[1,3,5]` 逐号映射、去重、排序、压缩：`[1,3,5]` 映射 1→2,3→4,5→1
  → 排序去重 → `[1-2,4]`。
- **删除号在标记中**：部分删除只移除该号（如上例）；**全部删除**则整段标记移除、
  该段落列入"标记被整段移除，需审校句子语义"。
- 上标/半角差异不做归一化；引擎只识别 `[数字(,/-)数字]` 形态（parse_manuscript 同口径）。

## 3. 文末列表重建规则

1. 删除的条目不出现（无空洞、无 "deleted" 占位）。
2. 存活条目按新序连续编号 1..M。
3. 每条文本来源优先级：Agent 手工 `work/reference_list.json` 原文（保留原措辞）>
   cite_engine render 按目标样式格式化（字段完整）> 最小回退（authors. title）。
4. `references.json` 每条保留 `source_file` + `source_index` 原始出处，可回溯到输入文件。
5. 新插入条目（insert_existing）获得新号；Agent 可在正文直接引用其**库编号** `[k]`，
   引擎按恒等映射把它转为新号。

## 4. 悬空引用（dangling）判定与处置闭环

- 判定时机：在**原始稿件**上按旧编号检测（重排后新号可能与旧删除号同值，不能比对重排结果）。
- 判定范围：除 reference_list 外所有 kind 的 numeric 标记；列表段里的 `[n]` 是条目标签，
  不算引用。
- 处置闭环（必须走满）：
  1. 引擎 FAIL，悬空清单给出 pid/kind/原文标记/涉及旧号；
  2. Agent 改写句子（删该引 / 改引存活条目 / 补引新条目），只动 text 与 cite_marks 结构；
  3. 重跑引擎 → 悬空清零 → 其余不变量通过 → PASS。
- 悬空未清零时**禁止**交付 success（status 至多 partial）。

## 5. 不变量终检（引擎 stdout: INVARIANTS: PASS/FAIL）

| 不变量 | 判定 |
|---|---|
| 正文最大编号 == 列表条数 | max(cite nums in body/notes/appendix/footnote) == len(entries) |
| 1..N 无缺口 | 每个 1..max 都被至少一处正文引用（插入但未被引用的条目会触发，提示 Agent 补引） |
| 无悬空 | 悬空清单为空 |
| 无样式混杂 | 正文只出现一种引用样式（numeric 与其他样式不共存） |
| 操作无错误 | ops_errors 为空 |

五项全过才 PASS；任一不满足 FAIL 且报告写明失败项。

## 6. 著者-出版年稿件的特殊规则

- 不做任何数字重排；正文 (作者, 年) 标记不动。
- 引擎检查：文末列表是否按第一作者排序（升序，不区分大小写）；缺 year/authors 的条目
  标 stale（排序键不可靠）。
- 报告输出排序结论与 stale 清单，供 Agent 人工确认；这构成该模式下的 PASS 依据。
