# 误报模式与人工复核要点

| 误报源 | 表现 | 复核动作 |
|-|-|-|
| 四舍五入差异 | 结果 65.2%、结论 65% 被判 approx（引擎）或被六维普查 verbatim 判"无出处" | 引擎 approx 条目一般采纳（统一精度即可）；**注意 six_scan 的 D6「结论数字在正文中无出处」只做逐字匹配，会把 65% 这类舍入误报为无源数字——第 7 步以 boundary_audit.json 的 verdict 为准，删除 scan 的该条** |
| 编号/年份误当数据 | "图1""[3]""2020"被当数字溯源 | 引擎已剔除；若仍出现（非常规写法如"见图 1"空格变体），删除并在 uncertainty 记录 |
| 单位换算差异 | 0.873 vs 87.3%、1.2×10³ vs 1200 被判 format_diff 或 stray | format_diff 按"需人工确认"处理；科学计数法漏判为 stray 时驳回并统一记数法 |
| 语义出处数字 | 结论引用的对比文献数据、常识常数被判 stray | 驳回：在 uncertainty 记录"出处为外部文献"；建议作者加引用编号 |
| 同义指标名 | 结果章叫"容量保持率 65.2%"，结论写"循环稳定性 65.2%"（数字 verbatim 命中 ok 但语义需核） | ok 条目仍需抽检语义对应 |
| 设计词漏检 | 方法章写了"设置空白组"但未含对照/随机等提示词 → 因果句判 unverifiable | 驳回并改判 supported（低置信度条目本就标了需人工确认） |
| 绝对词修辞用法 | "完全"修饰非结论性陈述（"完全按照文献方法"） | 删除：非结论强度问题 |
| 范围词在摘要 | 摘要"通用方法"与结论同句重复，被判两条 | 合并：保留结论处一条 |
| 讨论末段误判 | 讨论末段实为展望（含 limitation 词），被当结论目标句 | 接受：限制审计会判 adequate，其余条目人工删除 |

## 漏报高发区（Agent 第 7 步重点通读）

- 结论数字以文字形式出现（"提升近一倍""约九成"）——词面数字抽取的盲区；
- 隐性因果（"得益于""归功于"未在 CAUSAL_CUES 中）；
- 结论中的比较级无基线（"显著优于现有方法"但未指明对象与数据）；
- 限制说明有但避重就轻（只提未来工作、不提适用边界）——脚本判 adequate 时需人工再核。
