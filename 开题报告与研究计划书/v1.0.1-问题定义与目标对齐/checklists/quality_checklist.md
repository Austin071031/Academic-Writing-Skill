# 开题方案质量检查表（评审前逐项勾选）

## A. 立得住（研究问题与背景）
- [ ] 背景为“已知—未知—待验证”结构，而非领域综述或文献罗列。
- [ ] 每条“已知”均可定位到输入材料或文献（证据编号〔En〕）。
- [ ] 缺口由已知证据推导而来，且直接指向本课题的研究问题。
- [ ] 研究问题 1—3 个，每个可回答、可证伪（写有否定判据）。

## B. 对得上（目标—路线—验证—成果对齐）
- [ ] 每个研究问题有对应目标；目标数量与问题数量一致。
- [ ] 每个目标含指标、阈值及依据、样本/对照、时间点。
- [ ] 技术路线步骤与目标一一对应，步骤有输入/输出/依赖。
- [ ] 预期成果写清考核方式（主体、时点、标准）。

## C. 排得开（周期、经费、数据、人员）
- [ ] 阶段计划落在题目给定的周期内，含时间轴（年/季度/月）。
- [ ] 里程碑有交付物与验收标准，任务量与周期相容。
- [ ] 经费科目合计不超过给定预算；数据与人员条件逐项核对并标注。
- [ ] 关键路径标注正确，可并行部分已标出。

## D. 说得清（风险与可追溯）
- [ ] 风险覆盖数据获取/方法可行性/进度/伦理与合规，每条含触发信号、影响范围、备选方案、决策时点。
- [ ] 正文每个论断可经第 9 章映射表回溯到材料或引用。
- [ ] 正文引用编号 [n] 与参考文献一一对应；无未被引用的文献条目。
- [ ] 材料缺口、口径冲突、需人工确认事项单列一章，未静默假设。

## E. 交付与运行
- [ ] result.json 含 case.json output_contract 的全部字段与 case_id。
- [ ] proposal.md / proposal.docx / proposal.pdf / 首页 PNG 预览齐备，预览为真实渲染。
- [ ] 运行 scripts/validate_proposal.py 无硬性失败（hard_failures 为空）。
- [ ] status 诚实：材料缺失导致的不完整标为 partial，并在 uncertainty 说明。
