# 证据锚定与双向闭合规则（v1.0.0）

## 1. 采信规则

- 只从 `/input` 实际存在的文件采信；候选来自 extract_evidence.py，但采信前必须回到原文核对
  quote 与上下文（候选是正则粗抽，可能有边界误差）。
- 一条证据 = `{eid, source, locator, kind, name, value, quote}`。quote 为原文逐字摘录（≤220 字符），
  locator 为 `p.页码 行号`（PDF）或 `行号`（文本文件）。
- 材料中有而候选未覆盖的事实，用 `A001…` 自编 eid 补行，quote 逐字照抄原文。
- 同一事实多处出现时优先采信：实验日志（实际运行）> 配置文件（实验意图）> 代码默认值 >
  论文正文（作者转述）。采一个，其余进 unused_evidence.json 并写理由。

## 2. 锚点语法与改写规则

- 正文锚点写作 〔E0013〕，紧跟被支撑的数值或论断之后，一句可挂多个锚。
- 可以对 quote 做归并改写（如把 `learning_rate set to 0.0003` 转写为"学习率取 3×10⁻⁴"），
  但数值必须相等（3e-4 = 0.0003）；数值改写过 audit 时按字符串集合判定，转写须保留原值
  于参数表，正文可另写科学计数法并在 changes.json 留痕。
- 禁止：正文出现台账外的数字（含隐含推导值，如"约三个数量级"若无材料支撑）；
  禁止锚点悬空（〔E#〕必须存在于 provenance_map）。

## 3. 双向闭合

- 正向：正文每个数值/版本号/日期（白名单：≤12 的计数、19xx/20xx 年份、章节号）须在台账
  quote/value 中出现；audit_provenance.py 自动执行，泄漏清单含上下文片段。
- 反向：台账每条须被正文引用或在 unused_evidence.json 有理由；无理由未用即 fail。
- 附录B由 build_deliverables.py 自动生成，人不得手改；手改会在下次装配被覆盖。

## 4. 缺口分级

- high：影响复现或结论可比性（参数无来源、数据集版本不明、基线条件缺失）——必须追问作者。
- medium：影响完整性但不阻断复现（某子集规模未给、预处理细节缺失）。
- low：表述层（单位换算、缩写全称）。medium/high 未解决 → status=partial。
