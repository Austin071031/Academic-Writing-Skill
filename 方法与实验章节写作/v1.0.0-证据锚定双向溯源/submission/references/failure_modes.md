# 基础 Agent 在方法与实验章节上的典型失败模式（对照自查）

1. **只写主干漏要素**：写了"我们采用 Transformer 训练"却漏掉 batch size、epoch、数据集版本、
   种子、基线条件。→ 本版对策：七节骨架强制 + 六要素清单逐项核对。
2. **顺笔补数**：为段落通顺写"学习率设为 0.001"而材料里是 3e-4。→ 对策：audit 正向泄漏检查，
   泄漏 fail 必须改写或进附录C。
3. **条件串台**：把训练用的超参写进评测设置，或验证集条件混入测试描述。→ 对策：第二节
   训练/验证/测试分段写作 + scope 标注（见 parameter_table_template.md）。
4. **来源不可溯**：写了数值但不说是配置、日志还是论文第几页。→ 对策：锚点 + 附录B自动对照表。
5. **缺口隐藏**：材料没有的内容被静默省略或想当然补全。→ 对策：gaps.json 强制登记 +
   status 如实降级。
6. **版本含混**：数据集写"SynthBench"不带版本，复现者拿到 v1.3 必然失败。→ 对策：第四节
   版本与获取方式必查项，不明即 high 缺口。
7. **超时空手**：长时间解析大文件导致 result.json 不存在。→ 对策：Phase 0 先落骨架，
   预算告急时立即装配 partial。

每条对策的执行证据都在 build_report.json / audit_report.json 中可查。
