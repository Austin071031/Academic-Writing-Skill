# 模板与清单（v2 合并版：六要素清单 + 参数表 + 缺口追问）

# 六要素覆盖清单（七节骨架逐项核对）

写作前逐项问"材料里有没有"，写作后逐项问"正文写没写到、锚点挂没挂上"。

## 1 方法步骤
- [ ] 步骤有序编号，每步含输入/操作/输出
- [ ] 关键判断条件（停止条件、早退、筛选阈值）写明
- [ ] 没有把多步操作压成一句（检查"并""随后"连写的长句）

## 2 实验设置
- [ ] 硬件：机型/卡数/显存，带锚点
- [ ] 软件：框架与版本、CUDA、关键库版本，带锚点
- [ ] 训练/验证/测试流程分开描述，条件不串台
- [ ] 随机种子与重复次数写明；单次运行须声明

## 3 参数与来源
- [ ] 正文数值与附录A参数表逐行一致
- [ ] 每个参数有来源锚点（配置/日志/代码/论文页码）
- [ ] 跨来源取值不同时有取舍记录（changes.json）

## 4 数据集与划分
- [ ] 名称+版本（如 v1.2）、规模、来源/许可
- [ ] 预处理步骤与顺序
- [ ] 划分比例与随机方式（种子）、各子集用途
- [ ] 版本含混处已追问（防止复现失败）

## 5 对照实验
- [ ] 基线对象及版本/出处
- [ ] 对照条件是否同预算/同划分/同评测协议，写清
- [ ] 评价指标定义与统计方式（均值/最好/单次）

## 6 可复现清单
- [ ] 代码版本（commit/tag）与获取方式
- [ ] 环境（OS/Python/依赖版本）
- [ ] 训练与评测命令（可直接复制执行）
- [ ] 数据获取方式（URL/校验和/路径）

## 7 限制条件与适用范围
- [ ] 每条限制指向具体失效场景（"在 X 条件下不成立"，不写"存在一定局限性"式套话）
- [ ] 适用范围（数据域/规模/语言）写明

# 参数表模板（work/table_rows.json → 附录A）

每行一个参数：

```json
{"name": "learning_rate", "value": "3e-4", "unit": "—", "scope": "train", "source_eid": "E0005"}
```

字段规则：

- `name`：材料中的参数名（保留英文原名，正文可给中文释义）。
- `value`：与材料逐字一致的取值；单位并入 `unit` 时 value 只放数字。
- `unit`：单位或"—"；百分比、轮数、无单位均写"—"并在 value 体现。
- `scope`：作用对象与阶段，必须可辨认为 train/val/test/环境/通用之一，禁止"训练/评测通用"式含混。
- `source_eid`：支撑该取值的证据锚点；多源一致时填主来源，其余进 unused_evidence.json。

正文第三节的每个数值都要能在本表找到同行同值；build 后由 validate_output.py 做存在性检查，
数值一致性由 audit_provenance.py 的正向泄漏检查兜底。

# 缺口与追问清单模板（work/gaps.json → 附录C / result.json）

```json
[{"element": "对照实验", "desc": "基线结果数值未在材料中出现",
  "severity": "high|medium|low", "question_for_author": "请提供基线在 test 集上的 Accuracy 数值或其结果文件路径",
  "status": "unresolved|confirmed_by_material|written_with_caveat"}]
```

## 必须追问（high）的典型情形

1. 参数无任何来源（配置/日志/代码/论文都没有）。
2. 数据集只有名称没有版本或获取方式。
3. 基线对照的预算/划分/评测协议不明，无法判断可比性。
4. 日志与配置对同一参数给出不同取值且无法判定哪个生效。
5. 材料文件损坏、加密或权限不足无法读取。

## 追问句式（附录C展示用）

- "材料未给出 X 的取值/版本/条件；当前稿件未写入该值，请确认。"
- "A 文件记 X=v1，B 文件记 X=v2；本稿暂按优先级采信 v1，请确认。"

## status 语义

- `unresolved`：已追问未获确认 → 计入 result.uncertainty，status 至多 partial。
- `confirmed_by_material`：写作过程中在材料里找到了答案 → 正文补写并挂锚点。
- `written_with_caveat`：作者材料允许带保留地写（如"单次运行结果"）→ 正文写明口径。
