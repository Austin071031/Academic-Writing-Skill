# 管线规则与判据（v1.0.1）

## 设计原则

Agent 的时间只花在两件事上：**读懂材料**、**组织逻辑**；其余（格式、校验、渲染、汇总）
全部由管线保证。因此 mindmap.json 是唯一手写产物，字段规范见 SKILL.md。

## 结构质量判据（引擎强制）

| 判据 | 阈值 | 引擎动作 |
|-|-|-|
| 扇出 | >7 | 自动分组 |
| 深度 | >6 | 自动上提 |
| fact quote | 逐字子串 | critical |
| 数字 | 见于证据单元（含 % 换算） | warning |
| 边 | 端点存在、词表内、有证据 | critical/warning |
| 覆盖率 | 统计输出 | 供 Agent 参考补节点 |

## 分组语义

自动分组按两级键：(1) 节点 kind（问题/方法/证据/结论/任务/风险…）；(2) 无 kind 时按证据
材料来源（M01/M02…）。分组节点 kind="group"、note 注明"引擎自动分组"。
若分组不合语义，Agent 应手工调整 mindmap.json（改名或重挂）再重跑——引擎是助手不是替代。

## 效率账（相对基础 Agent）

| 动作 | 基础 Agent | 本管线 |
|-|-|-|
| 排版四种可编辑格式 | 手工，易错 | 秒级 |
| SVG/PNG 预览 | 通常无法产出 | 自动 |
| 证据逐字核验 | 不可能全量 | 全量 |
| 结构修复 | 返工重写 | 自动分组 |
| 交付清单/契约回填 | 手工整理 | 自动 |

## 何时不用引擎修复

导图是强叙事结构（如严格按照时间轴）且扇出超标是有意设计时：先 `engine.py fix` 看
change_log，再手工还原需要保留的宽扇出，最后直接跑 map_audit/map_render/assemble。
