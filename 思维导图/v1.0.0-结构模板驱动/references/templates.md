# 模板库与填写规则（v1.0.0）

## 材料类型判定

`templates.py` 用计分制关键词匹配（任务说明 + 材料前 40 单元）判定五类之一，
判定结果写入 skeleton.json 的 `material_type`。若任务说明与判定冲突，以任务说明为准：
直接在 mindmap.json 中采用其他模板的分支维度即可（模板是脚手架，不是枷锁）。

## 五类模板的分支维度与常见问题

### 论文（IMRaD）
研究问题与目标 / 背景与研究缺口 / 方法 / 结果与证据 / 结论 / 局限与展望。

- 问题节点：用材料原话表述科学问题，禁止泛泛"研究背景很重要"。
- 方法节点：方法名 + 关键参数（参数是数字，必须溯源）。
- 结果节点：只收定量或定性明确的发现；每个结果挂结果章节单元。
- 结论与结果分离：结论是作者推断，至少一条 supports 边来自结果节点。

### 综述
主题范围 / 分类框架 / 主要流派 / 共识 / 分歧 / 研究空白。

- 流派子节点挂代表性证据单元；共识与分歧分开，分歧用 contrasts/conflicts 边。

### 实验方案
目标与假设 / 变量（自变量/因变量/控制）/ 步骤（precedes 边）/ 对照与基线 / 判定标准 / 风险。

- 判定标准中的阈值数字必须逐字见于证据单元。

### 项目计划
总体目标 / 里程碑（precedes）/ 任务（depends_on）/ 交付物 / 风险。

- 负责人与截止时间写入节点 note；材料未给则标 uncertain。

### 会议纪要
议题 / 结论与决议 / 分歧（conflicts）/ 待办（action，负责人+截止）/ 风险。

## 填写纪律

1. 槽位节点是"问题"，填好的节点是"答案"——标题必须是材料中的实质内容，不得保留
   "研究问题与目标"这类模板名作为最终节点。
2. 每个事实节点挂 1–3 条 evidence；多于 3 条说明节点应拆分。
3. 节点标题 ≤30 字，细节放 note。
4. 材料没有的分支保留槽位并标 `status="missing"`；不确定标 `"uncertain"`。
5. 同级节点保持同一分类维度（都是方法、或都是结论），避免混杂。
