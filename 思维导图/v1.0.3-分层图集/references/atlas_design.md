# 图集设计规则（v1.0.3）

## 为什么分层

认知研究与工具实践一致：单图 30-40 节点是可读上限。超过后应"总览 + 详图"分层，
而不是缩小字体硬塞。本 Skill 的预算（总览 20 / 详图 40）即据此设定，可用参数调整。

## 一级分支设计（Agent 的核心决策）

原则：**互斥、穷尽、同维度**。按材料类型参考：

| 材料类型 | 推荐一级分支 |
|-|-|
| 论文 | 研究问题 / 方法 / 结果与证据 / 结论与局限 |
| 综述 | 范围与框架 / 各流派（每流派一支）/ 共识与分歧 / 空白 |
| 实验方案 | 目标与假设 / 变量与对照 / 步骤 / 判定标准 / 风险 |
| 项目计划 | 目标 / 里程碑 / 任务与依赖 / 交付物 / 风险 |
| 会议纪要 | 议题与结论 / 分歧 / 待办 / 风险 |
| 多文档合集 | 每文档一支，或按主题跨文档重组 |

避免：按材料页码分段（"第一部分/第二部分"）——那是切分不是组织。

## 拆分语义

- 总览图保留根 + 一级分支，分支节点 note 自动追加"分支规模 N 节点 → 详见 topic_XX"。
- 详图以分支节点为新根，保留其全部子树；超预算分支截断到二级（截断事实写 uncertainty）。
- 跨分支的 edges：两端同图时随图渲染；跨图边保留在 work/mindmap.normalized.json，
  索引中可回查——这是图集模式允许的已知取舍。

## 编号纪律

- 节点 id 一旦写入 mindmap.json 不再变动；图集拆分不改 id。
- 引用某个想法时，"图 + 节点 id + 单元号"三元组可唯一定位（如 topic_02 / n14 / M01-S03-P002）。
