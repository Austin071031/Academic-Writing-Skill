# 一致性复核清单

## 机读审计覆盖（engine_check 自动执行）
| 检查 | FAIL 条件 | 处置 |
|-|-|-|
| 摘要↔正文 | 摘要数字未在正文出现 | 改摘要或改正文，使数字一致且有材料出处 |
| 图/表引用↔注 | 正文引用图 N 但无图 N 注 | 补图注或删引用 |
| 方法↔结果 | 方法宣布的分析结果节未报告 | WARN：补结果或删方法虚写 |
| 缩写首用 | 缩写未给全称 | WARN：首用处补全称 |
| 待确认闭环 | 存在【待确认】/【待补】 | 全部进 uncertainty，人工逐条复核 |
| 改稿留痕 | 有段落级改动但 change_log 空 | WARN：补写留痕 |

## change_log.md 格式
```markdown
- [改写] P003 "效率很高" → "处理组产率 92.3% ± 1.8%" — 依据：M02#l14
- [删除] P007 与 P003 重复的对照组描述 — 依据：冗余
- [数字] P005 "61%" → "61.2%" — 依据：M01#row2 原始数据
- [移动] 图 2 图注从附录移回结果节 — 依据：结构规范
- [待确认] P009 底稿"显著提升"无检验依据，改为"提示提升" — 依据：材料无统计检验
```
类型：改写/删除/新增/数字/单位/移动/格式/待确认。每条必须有依据（材料锚点或任务要求）。

## 人工复核点（交付时向作者明示，写入 uncertainty）
1. diff_review 中每段删除/改写是否故意；
2. 底稿有但材料查不到的数值（保留+标注的部分）；
3. 图片材料中的数值；
4. 材料互相冲突处的口径取舍。

## 校对任务勘误表格式
`| 位置 | 底稿表述 | 材料依据 | 处置（改/删/标待确认） |`
勘误表附在 audit_report 之后或直接作为正文交付物（按任务要求）。
