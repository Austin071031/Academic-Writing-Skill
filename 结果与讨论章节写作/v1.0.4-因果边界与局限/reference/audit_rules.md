# 因果审计脚本判定细则（check_causal.py）

## A1 因果动词审计

- 词表：导致、引起、造成、证明了、决定了、归因于、leads to、results in、proves that、demonstrates that、is responsible for。
- 豁免条件（满足其一即通过）：
  1. 句子带 `<!-- Kx -->` 锚，且 design_notes.md 中存在 `Kx ... 级B` 登记；
  2. 句内含降级标记（推测/可能/提示/有待/may/might/suggest/speculation 等）。
- 误报处置：转述他人文献中的因果表述时，给该句加文献锚【文献：…】并在 design_notes 补一行说明；仍被脚本拦截时，修改措辞为转述式（"该研究观察到……"）或在 uncertainty 记录误报。

## A2 结果段机制词汇

- 词表：机制、通路、介导、通过……起作用/发挥作用、mediate、mechanism、pathway。
- 结果段出现即 fail（机制讨论属于讨论段且需标注）；例外：材料图注本身以机制命名指标（如"apoptosis pathway score"）时，改用指标原文并加引号，或在 uncertainty 记录误报。

## A3 局限四层覆盖

- 局限文本（从"局限/limitation"标题起的小节，或讨论段中含"局限"的句子）须覆盖：方法、样本、测量、统计（中英文词表均识别）。
- 缺失层报 fail 并在 detail 列出；若材料确无该层局限，人工确认后在 uncertainty 写明"未发现{层}层面的实质局限"，并在正文中保持该判断有据。

## A4 改进方向

- 每条含"局限/不足/限制"的局限句须含改进词（未来、可、有待、需、future、further、next、should 等）。
- 注意 A4 与 A3 联用：局限句同时缺层缺改进时，两处都会报，一次修改即可同时消除。

## 审计后的措辞联动检查（脚本不做，人工必做）

1. 正文因果句定级与 design_notes 一致；
2. 局限段提到的威胁对象与正文论断对应；
3. 局限段写到的统计问题（如未校正混杂）与正文相应结论的措辞强度一致（未校正混杂却写"证明"即矛盾）。
