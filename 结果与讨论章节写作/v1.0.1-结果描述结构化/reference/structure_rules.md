# 结构自检脚本判定规则（check_structure.py）

## 小节切分

脚本按 `## 结果` / `## Results`（结果）与 `## 讨论` / `## Discussion`（讨论）标题切分。若 task.md 要求其他标题（如中英文混排 "3 Results and Discussion"），写作时仍须用可识别的两级标题，否则 R 系列检查无法运行。

## R1–R3 词汇扫描

- 扫描范围仅限结果部分；讨论部分不受 R1–R3 约束。
- 命中即 fail，detail 给出句序与句前 120 字。修改方式不是简单删词，而是把解释内容**移**到讨论段并补锚点（见 style_lexicon.md 第 2 节替代写法）。
- 已知误报：英文 "data are shown in Figure 2" 中的 "are" 与正则无关；中文"如图2所示"不含解释谓词，不会命中。若误报发生，在 uncertainty 记录。

## R4 段落锚点

- 锚点正则：`图N / Fig. N / Figure N / 表N / Table N / 图SN / Table SN`。
- 每段至少一个；纯过渡段（如模式 B 的问题引入段）若确实无图，可合并到相邻段，或在 uncertainty 说明。

## R5 段落均衡

- 计算结果部分各段字符数；最长/最短比 ≤ 5 判 pass。
- 例外：全文只有一段结果时跳过（无离散度可言）。

## R6 推测标注

- 讨论部分出现 推测/speculat/可能机制 等词时，同一语句或下一句须出现 待验证/to be tested 等标注，否则 fail。
- "可能源于样本差异"这类文献不一致的归因解释不在此列（R6 只管机制推测），但建议在 uncertainty 或正文中注明这是解释而非数据事实。

## R7 发现覆盖

- outline.md 中所有 `F数字` 编号必须在正文中以 `F数字` 形式出现一次以上（写作时可在段尾注释 `<!-- F1 F2 -->`，交付稿保留或删除均可，但自检须在删除前运行一次，或保留注释）。
- 推荐做法：正文段落后保留 HTML 注释锚点，既便于复核又不影响渲染。
