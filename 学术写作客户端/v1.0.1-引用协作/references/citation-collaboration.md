# 引用协作方法说明

## 引用依赖图

以正文首次出现顺序为权威构建引用序列 `first_order`。对顺序编码制
（Vancouver / GB/T 7714 顺序编码），参考文献表的正确编号 = 首次出现位次。
`order_map[旧号] = 新号` 是全部变换的唯一来源，任何一处新编号都可由它解释，
这就是“可逐条回溯，不新增材料外事实”的机械化保证。

## 审计规则

1. `order-mismatch`：第 k 个首次出现的编号不等于 k；
2. `missing-reference`：正文引用的编号在文献表中不存在；
3. `uncited-reference`：文献表条目从未被正文引用；
4. `doi-missing`：条目缺少 `10.NNNN/...` 形态 DOI。

审计只报告不修复。修复（sync）必须来自任务指令授权。

## 同步实现要点

- 正文引用重写：`docxkit.renumber_citations` 跨 run 替换，保留字符格式；
  替换后区间自动压缩（`[2,3,4]` → `[2-4]`），多重引用去重排序。
- 文献表重排：按 `order_map` 的新序摘下段落再插回，同时更新每条的
  `[n]` 前缀。未引用条目保持在表尾并按确认项处理，不擅自删除。
- 每处改写记录 `{para_index, old_raw, new_raw}`，写入 sync_report.json。

## 与其他方向的关系

引用同步常与定点修改同时出现：本 Skill 允许在同步后的稿件上继续执行
其他修改指令，所有改动共用同一份 changes 台账纪律。修订标记（v1）、
版本快照（v3）、保真导出（v4）为相邻能力，不在本方向重复实现。

## 核验清单

1. 同步后审计 `order-mismatch` 清零；
2. `audit_diff` 结构要素零变化；
3. order_map 覆盖正文全部引用编号，无遗漏；
4. result.json `missing_fields` 为空。
