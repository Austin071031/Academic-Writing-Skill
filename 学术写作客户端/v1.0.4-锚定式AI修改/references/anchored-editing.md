# 锚定式编辑方法说明

## 四步闭环

1. **指令分解**：自然语言指令 → 原子改动集合。每条只含一处局部文本、
   一个改动层面（措辞/术语/结构/引用/核对）、一句依据。
2. **锚点定位**：机器锚定（标题/引文/关键词三级回退）与人工分解的 old
   互相印证；找不到唯一锚点就不改。
3. **最小改动**：跨 run 替换摊回原 run，格式属性随原 run 保留；
   只重写 document.xml，其余部件原字节写回。
4. **漂移守卫**：交付前的机械核验，四类判定见 SKILL.md 阶段 4。

## 漂移守卫的判定逻辑

- 锚定校验：改动 old 是否逐字存在于原稿；
- 改写比：`difflib` opcode 差异字符 / 段落长度，阈值默认 0.5；
- 未授权改动：发生变化且不在任一改动锚点（含 old 所在段）±1 邻域内；
- 数字守恒：对齐后段落数字集合的消失项是否被改动目标覆盖。

对齐策略：先精确匹配未变段落，再对剩余做 ±3 容差最优对齐，
因此对插入/删除段导致的位移稳健。

## 为什么需要脚本守卫

模型在压力下倾向“顺手优化”邻近句子；提示词约束无执行保证。
守卫脚本输出结构化报告（drift_report.json），评审与作者可直接复核
“改得准、改得小、没改别处”。

## 核验清单

1. drift_report `verdict=clean`；
2. changes.json 每条 status 为 applied/verified-no-change，
   无 failed-text-not-found；
3. audit_diff fidelity_breaks 为空；
4. result.json missing_fields 为空。
